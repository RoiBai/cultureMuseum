# 视觉荆楚：内容维护与研究约束

本 demo 用静态 JSON 驱动：`dist/data/artifacts.json`。暂未连接数据库。网页模板和 WebGL 渲染代码与内容分离；目前模板渲染首件器物，新增条目进入数据后仍需增加目录选择入口，不能宣称任何器物可直接套用已完成上线。

## 提案如何落在本例

- 研究核心：具体形态、色彩、组织、意象与文化语境的关系。`lenses` 是阅读视角；`relations` 保存有方向、有类型、有依据的实体联系。
- `hotspots` 必须对应具体图片局部。`observation` 是项目形式观察，`fact` 是馆方记录，两者分开。
- `sources` 保留具体来源、支持范围、图像作者、许可及显示状态。馆方照片和展陈照片不能合并成未经证实的原貌。
- 多源互证需要论点级的关联；当前证据覆盖馆藏记录、考古音乐文物综述和两份照片。尚无能够支持本件器物具体解释的文学/景观关联，故不强行填充《楚辞》或文化景观。
- “有据”对应来源；“有境”对应年代、出土背景及同墓乐器；“有形”对应五维阅读；“有用”对应可定位的高清查阅；“有人、有续”需要后续学生维护、教师审阅及版本记录的工作流程，不以宣传文字替代。

## 学生的维护输入

1. 确认到“哪一件”，不只确认同类型器物。提供名称、出土地、墓号、馆藏机构和逐项来源。
2. 保留原始图片与署名；不以生成图、锐化补细节或其他版本替换物证。新增图片必须记录日期、许可、是否经过处理、与其他图像的状态差异。
3. 为每个观察点写一段形式观察、一条有据事实，再填写原图归一化坐标。照片更换后重新核验坐标。
4. 关系记录包含 from、to、type、label、evidenceType、sourceIds；形式相似不等同于历史传承。
5. 在五个 lenses 中选择有证据支持的解释。缺失资料保留为维护问题，不自动生成史实。
6. 运行 `node scripts/validate-content.mjs`，在本地预览逐项检查照片位置、引用和手机操作，记录修订后再发布。

## 当前素材

- 展台：馆方 700×600 原图，通过运行时去白底和有限角度透视形成空间展台。原始 JPEG 未改动。它不是文物扫描模型，也不提供背面信息。
- 高清查阅：三十三画生于 2021-12-23 的 5504×8256 展陈实拍，CC BY-SA 4.0，原文件未改动。网页仅缩放、平移。照片显示完整鼓面，馆方图片可见鼓框；补配/复制状态未获权威说明。
- WebGL 分层仅解释视觉组合，不是科学拆解复原。没有使用 AI 生成文物纹饰。
- 已按用户意见移除色彩卡、下载、随机配色功能。色彩入口用于定位原图与实拍细节。

## 后续维护 skill 的固定流程

“读来源 → 建资料草稿 → 标注观察点和关系 → 校验 → 出预览与差异清单 → 审阅 → 保存版本”。Skill 可组织和检查资料，不能自动决定尚未证实的历史解释。当前未安装或创建用户级 skill。
